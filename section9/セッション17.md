# セッション17
## 認証機能の追加

### メールアドレス/パスワードでのログイン
`AuthService`(`shared/auth.service.ts`)にFirebaseの`AngularFireAuth`をラップして実装。

- `signUp(email, password)` : 新規登録
- `login(email, password)` : ログイン
- `logout()` : ログアウト
- `getAuthState()` : 現在のログイン状態を常時監視するObservable

#### メールアドレスの制約

| 入力 | 結果 | 理由 |
| --- | --- | --- |
| `test@example.com` | ✅ OK | 標準的な形式 |
| `abc` | ❌ NG | `@`がない |
| `abc@` | ❌ NG | `@`の後ろがない |
| `abc@example` | △ 環境による | ドット(`.`)以降のドメイン部分がないと弾かれることが多い |
| `abc@example.com` | ✅ OK | 標準的な形式 |

#### パスワードの制約(Firebase側の最低要件)

| 入力 | 結果 | 理由 |
| --- | --- | --- |
| 5文字以下 | ❌ NG | Firebaseの最低要件は6文字以上 |
| 6文字以上 | ✅ OK | Firebase側の最低要件を満たす |

アプリ側の`login.component.ts` / `signup.component.ts`でも`Validators.minLength(6)`を設定し、Firebase側のエラーが出る前にフォームでチェックしている。

### ルートガード(未ログイン時のアクセス制限)
`/hoge`や(将来追加する)`/results`などに、未ログインでも直接URLを打てば入れてしまう問題があったため、`AuthGuard`(`shared/auth.guard.ts`)を実装。

- `canActivate` / `canActivateChild` の両方を実装し、`getAuthState()`でログイン状態を確認
- 未ログインなら`/login`にリダイレクトし、`false`を返してそのルートへの遷移を止める

`pages-routing.module.ts`では、`login`/`signup`だけをガードの外に出し、それ以外(トップの`start`、`hoge`、今後追加する`results`/`settings`など)を1つの親ルートにまとめて`canActivateChild: [AuthGuard]`を1回だけ適用。これにより新しいページを追加してもガードの付け忘れが起きない構成にした。

```ts
children: [
  { path: 'login', component: LoginComponent },
  { path: 'signup', component: SignupComponent },
  {
    path: '',
    canActivateChild: [AuthGuard],
    children: [
      { path: 'hoge', loadChildren: () => import('./hoge/hoge.module').then(m => m.HogeModule) },
      { path: '', loadChildren: () => import('./start/start.module').then(m => m.StartModule) },
    ],
  },
]
```

### ログイン画面からサインアップへの導線
未登録ユーザーがログイン画面で詰まらないよう、`login.component.html`の下部に`/signup`へのリンクを追加。

### ログイン成功後の遷移先の修正
`login.component.ts`で`this.router.navigate(['/pages'])`としていたが、`/pages`というルートは存在しないため、ワイルドカードルートに引っかかりトップ(`''`)に戻されるだけの不要なリダイレクトになっていた。`this.router.navigate(['/'])`に修正。

### ログイン状態の保持について
Firebase Authはデフォルトで永続化方式が`LOCAL`のため、ブラウザに保存されたログイン情報は`ng serve`を再起動しても消えない(サーバーの再起動とログイン状態は無関係)。今回はこの標準動作(`LOCAL`)を維持する方針とした。

### ログイン中の表示・ログアウトボタン
`header-component`に`AuthService`を注入し、`getAuthState()`の結果をもとに`*ngIf`でログイン中のみログアウトボタンを表示。ボタン押下で`logout()`→`/login`へ遷移。

- メールアドレスの表示は不要と判断し削除
- サイドメニューにも一度追加したが、ヘッダーと重複するため削除しヘッダーのみに一本化

## セッションのまとめ
メール/パスワードでの登録・ログイン・ログアウトが一通り動く状態になった。ルートガードにより未ログイン時のURL直打ちアクセスも防止できている。

### 残っているタスク
- `results`(成績)・`settings`(設定)ページ自体がまだ存在しない(サイドメニューにリンクのみ)。ページを作る際は`canActivateChild`配下の`children`に追加すれば自動的にガードがかかる
- 新規登録→ログイン→ログアウトの一連の流れを、実際のFirebaseプロジェクトで最終確認する

## Tips
- `canActivate`と`canActivateChild`はロジックが同じなら、`canActivateChild()`の中で`canActivate()`をそのまま呼び出せば実装を二重に書かなくて済む
- Firebase Authのログイン永続化(`LOCAL`/`SESSION`/`NONE`)は`ng serve`の再起動とは無関係。ブラウザのストレージに紐づいている
